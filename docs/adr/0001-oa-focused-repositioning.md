# ADR-0001：定位收缩至 OA / 国产中间件专项检测

- 状态：已接受（Accepted，2026-08-24）
- 版本：v1
- 决策人：项目作者（solo 维护者）
- 关联文档：`docs/audit/rayscan-evolution-plan-2026-07-12.md`（§11 战略修正）、`docs/OA_RULES.md`、`docs/audit/rayscan-s4-trust-rebuild-2026-08-24.md`（执行清单）

## 决策问题

RayScan 作为个人维护的安全工具，下一个版本周期把有限的开发资源押在哪里？

## 上下文与驱动力（Forces）

| # | 驱动力 | 依据 |
|---|--------|------|
| F1 | 单人维护带宽有限 | 18 个检测模块 + 7 个集成层 + Web UI + 旧 GUI，技术债文档 TD-005 自认 65 次单人直推无评审 |
| F2 | 通用扫描赛道已无胜算 | nuclei（12.5w 免费模板）、xray、ZAP 成熟且免费；演进规划 §11.1 已自我诊断"自研内核优先的假设不成立" |
| F3 | 中文 OA / 国产中间件是真实空白 | nuclei 对国产 OA 覆盖稀疏，xray 社区版无 OA 专项，AWVS 收费——机会窗口真实存在 |
| F4 | 三级检测链路地基已建好 | S3 已实现：内容指纹识别 → 版本识别 → 规则级响应证据验证 + 版本过滤，架构方向与 OA 专项定位天然匹配 |
| F5 | 信任层已失真 | README 宣称 190 测试（实测收集 259），OA 规则闭环 0/12，宣称与交付之间存在断层 |

## 决策

> RayScan 定位收缩为：**中文 OA / 国产中间件专项检测器，规则级证据链，一条命令出可复核报告。**

具体含义：

1. 自研检测精力全部投向 OA 规则的**实测闭环**（靶场验证 + 响应证据记录），目标见适应度函数 FF3。
2. 通用漏洞检测交给内置 Nuclei 阶段兜底（已接入主流程），不再新增自研通用检测模块。
3. 项目评估口径收敛为两个数：**OA 规则闭环率** 与 **误报率**，对外宣称以此为准。
4. 与演进规划 §11.2 的关系：本 ADR 是 §11 战略修正的正式固化。§11.2 已砍掉的方向（IDOR/越权自研、SPA 爬取、Web UI 深化、MSF 验证链、多引擎聚合深化）**继续维持砍掉状态，不因本 ADR 复活**。

## 已拒绝的备选方案

| 备选 | 拒绝原因 |
|------|---------|
| 继续做"全栈通用 Web 漏洞扫描器"（v2.x 现状惯性） | 与 nuclei/xray 正面竞争，单人无带宽；§11.1 已诊断该定位假设不成立；维持现状只会加深宣称与交付的断层 |
| 多引擎聚合（AWVS/Nessus 调度） | 依赖闭源商业系统 API；7 个集成文件已写完却未接入主流程，属于纯维护负担；与个人项目"可自主掌控"的约束冲突 |
| 继续铺新检测模块（IDOR、认证绕过等） | §11.2 已明确砍掉；新模块稀释 OA 闭环所需带宽，且每加一个模块都在扩大 151 处裸异常捕获的风险面 |
| 什么都不做（保持模糊定位） | 定位漂移已发生多次（v1.1 自研内核 → v1.2 OA 专项 → v2.1 又加了编排层/被动扫描等横向功能）；无决策记录会导致方向反复 |

## 后果

| 正面 | 负面 |
|------|------|
| 差异化可防守：空白市场 + 中文规则/社区壁垒，nuclei 短期不会补齐国产 OA 长尾 | 通用检测能力增长停滞，依赖 Nuclei 兜底，Nuclei 覆盖不到的场景不再自研 |
| 规则库可积累、可社区共建：贡献一条 OA 规则远比贡献一个检测器门槛低 | "全栈扫描器"的 README 卖点需要重写，前期宣传的沉没成本需承认 |
| 评估口径变简单：闭环率、误报率两个数字即可对外证明进步 | 若 OA 闭环推进失败，定位需要再次转向（见可逆性） |
| 与已有三级检测链路（F4）零架构改动对接 | 部分已写代码（awvs/nessus/msf 集成层、scheduler、session_manager）沦为明确的"冻结/待处置"资产 |

## 可逆性与重新考虑触发条件

- **门型**：双向门（可逆）。收缩定位不删除通用检测代码，Nuclei 阶段继续服务通用场景。
- **撤销成本**：低。主要成本是 README/文档措辞回改，无架构性返工。
- **重新考虑触发条件**（满足任一即应重开本 ADR）：
  1. S5 结束时（约 3 个月后）OA 闭环 < 3 种（连公开靶场都搭不起验证环境）；
  2. Nuclei 社区出现系统性覆盖国产 OA 的模板体系，差异化窗口关闭；
  3. 项目获得持续的多维护者投入，单人带宽约束（F1）消失。

## 责任

- **决策责任人**：项目作者。
- **检查路径**：本 ADR 的达成度由适应度函数 FF1–FF6 度量（见下），全部可本地/CI 执行；S4/S5 执行清单见 `docs/audit/rayscan-s4-trust-rebuild-2026-08-24.md`。

## 适应度函数（引用）

| ID | 不变量 | 阈值 | 检查方式 |
|----|--------|------|---------|
| FF1 | CLI 不含业务编排 | `cli.py` ≤ 600 行且 import 白名单 | CI 行数检查 |
| FF2 | 宣称数字 = 实际数字 | README 测试数与 `pytest --collect-only` 一致 | CI 校验或动态徽章 |
| FF3 | OA 规则闭环推进 | v2.2 发布前 ≥ 6/12 已实测验证 | 解析 `OA_RULES.md` §5 验证表 |
| FF4 | 靶场回归基线 | Metasploitable2/DVWA 已知真阳性集合不回归、无误报新增 | 端到端测试（待建） |
| FF5 | 裸捕获不增 | `except Exception` 无日志吞错计数单调递减 | ruff BLE001/S110 计数门禁 |
| FF6 | 仓库结构卫生 | 僵尸入口/嵌套目录数 = 0 | `git ls-files` 白名单检查 |
