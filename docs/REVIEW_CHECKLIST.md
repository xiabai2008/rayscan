# 代码评审清单（Code Review Checklist）

本清单用于 RayScan 所有 Pull Request 的评审。评审人应逐项确认，**高严重度项（🔴）未通过不得 Approve**。

> 用法：评审时在 PR 评论中逐项勾选；可在 PR 模板的基础上补充。质量门禁（ruff / pytest / coverage）由 CI 自动把关，本清单聚焦「机器查不出、但人能看出来」的问题。

---

## 🔴 安全正确性（扫描器核心，错漏即误报/漏报）

- [ ] **Payload 不会对被测目标造成破坏**：无写文件、无不可逆操作、无超出授权范围的探测。
- [ ] **无硬编码凭据 / Token**：密钥、URL、内部地址不入库（或走配置 + 环境变量）。
- [ ] **注入类逻辑正确**：SQLi/XSS/CMDi 的判定基于响应差分，而非简单字符串包含导致的误报。
- [ ] **超时与取消**：所有网络/子进程调用都有超时；扫描可被用户中断（无无限阻塞）。
- [ ] **异常处理不吞错**：`except` 必须记录日志；禁止裸 `except:` 或 `except Exception: pass`。
- [ ] **并发安全**：共享状态（缓存、连接池、速率限制器）在多线程/异步下无竞态。

## 🟡 性能与资源

- [ ] **无阻塞式串行瓶颈**：I/O 优先使用已有的 `HTTPPool` / 异步路径，避免逐请求新建连接。
- [ ] **无内存无限增长**：大响应体、爬取队列有上限或流式处理。
- [ ] **速率限制生效**：对外请求遵守 `IntelligentRateLimiter`，未绕开。
- [ ] **外部进程（Nuclei/sqlmap/ffuf）有超时与资源上限**，不会挂起 CI / 宿主机。

## 🟢 可读性与可维护性

- [ ] **命名自解释**：函数/变量名表达意图，魔法数字提取为常量（放 `constants.py`）。
- [ ] **单一职责**：函数长度可控，复杂逻辑有注释解释「为什么」而非「是什么」。
- [ ] **无重复代码**：公共逻辑抽到 `base.py` / `core/` 复用，而非复制粘贴。
- [ ] **改动聚焦**：一个 PR 只做一件事，无无关重构混入。
- [ ] **遵循 ruff 规则**：`ruff check` / `ruff format --check` 通过（CI 门禁）。

## 🔵 测试

- [ ] **新功能有测试**：检测模块新增/修改附带 `tests/test_<module>_detector.py`。
- [ ] **测试可独立运行**：不依赖外部网络/真实目标；用 fixture / mock。
- [ ] **回归覆盖**：修复的 bug 有对应回归用例，防止复发。
- [ ] **测试通过**：本地 `pytest tests/ -q` 全绿，且 CI 矩阵（3.9–3.12）通过。

## 🟣 文档

- [ ] **公共 API / CLI 变动同步文档**：README、CLI help、`docs/` 相应更新。
- [ ] **新增配置项写进 `config` / 示例**：使用者可知如何开启。
- [ ] **破坏性变更在 PR 描述中明确说明**迁移方式。

---

## 评审礼仪

1. 先理解改动意图，再挑问题；评论对事不对人。
2. 高严重度问题必须解决；风格类建议可用 「nit:」前缀，不阻塞合并。
3. 评审对话需 **Resolve** 后方可合并（分支保护已强制）。
4. 需要更多上下文时，直接在 PR 里 `@` 作者提问，或约 10 分钟结对看代码。
