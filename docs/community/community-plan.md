## 三、内容日历(周更模板)

> 核心原则:**每周必须让用户看到一个"进展"**。即使只有一条 `rules` 更新,也要发。

### 3.1 周更模板(固定栏目)

```
标题:RayScan 周报 #N — <本周主题>

1. 🚀 本周更新
   - <功能/修复列表>(引用 GitHub Release / commit)
2. 🧪 本周 Demo
   - 用 `rayscan demo` 演示一个新场景(附截图/动图)
3. 📈 社区数据
   - Stars / PR / Issue 数量变化
4. 🙏 感谢贡献者
   - @user 提交了 <PR 内容>
5. 🔮 下周预告
```

### 3.2 月度深度文(选题池)

| 主题 | 目的 |
|------|------|
| 《用 RayScan --explain 做一份可提交的 SRC 报告》 | 展示可解释性差异点 |
| 《被动扫描为什么是 SRC 的必修课》 | 教育市场,带出 passive 功能 |

## 四、贡献者激励体系

### 4.1 贡献者成长路径

```
新用户 → Star/使用 → 提 Issue → 修文档/翻译 → 修 bug →
新增检测规则(模板) → 新检测模块 → 核心维护者
```

### 4.2 具体激励

| 层级 | 激励 |
|------|------|
| L1 使用者 | Issue 响应承诺(<48h 首次回复) |
| L2 贡献者 | `CONTRIBUTORS.md` 致谢名单 + Release 点名 |
| L3 规则贡献者 | 规则署名 + 规则数据统计页 |
| L4 维护者 | 提交权限(Triage/Write) |

### 4.3 反馈闭环承诺(写入 README)

- 所有 Issue **48 小时内首次回应**(即使结论是 wontfix)
- 每个合理 PR **7 天内评审**
- 感谢标签 `good-first-issue` / `help wanted` 持续更新,降低新人门槛
